# X / BOG 新主串与无饼干提示

日期：2026-09-07。分支 `feat/reader-scroll-kaomoji`，基于 v0.0.3，首发版本 v0.0.4。

## 原因与范围

v0.0.3 只开放外站回复能力，`Publish=false`，所以 `c` 无法发新串，底部也不显示发串提示。本次为 X 和 BOG 开放新主串，复用现有饼干隔离、编辑器、颜文字、附件选择、草稿和确认发布流程。外站 SAGE、删除恢复、我的内容、领取饼干仍不支持，菜单按相应独立能力显示。

TUI 先按 `b` 选择具体板块，再按 `c` 编写新串；时间线不能作为发布目标。`Ctrl+P` 预览当前站点、身份、板块、正文和附件，Enter 才提交。CLI `thread create --board 编号` 使用 `board list` 返回的编号；`draft publish` 同样支持新串。未确认或 `--dry-run` 不请求提交表单、不上传附件。

按 `c/r/R` 时若未选饼干，饼干弹窗顶部显示“没有饼干，无法发串/回复串”及“请先导入或选择当前岛的饼干。”提示占用的行数计入菜单滚动布局，44×16 窗口也能看到说明、首项与操作提示。单独按 `i` 进入管理不会保留该错误说明；选择身份后可重新发串/回复。

## X 发串

- 根据 API `getForumList` 将选中板块编号解析为名称，GET 当前网页站点的 `/f/板块名称`。网页的 `/f/4` 并不等同于综合版1，不能以编号直接拼接该路径。
- 使用当前提交独立的 Cookie jar，读取唯一 POST 表单 `/Home/Forum/doPostThread.html`；要求 `fid` 等于选择的 API 板块编号，存在本次 `__hash__` 和可用 `content`。回复继续使用 `/Home/Forum/doReplyThread.html` 与 `resto`。
- 标题和正文遵守既有客户端上限及表单 maxlength；图片最多一张，与正文一起 multipart 提交，不进行独立上传。
- 默认 API 对应网页域名仍是显式映射，自定义 endpoint 不回落到官方站点。保留表单会话，不跟随重定向、不提交跨源 action。

## BOG 发串

- 使用本地板块编号查找导航中的真实板块名称，GET `/f/板块名称/1`。本地 CRC32 编号只用于导航和草稿绑定，绝不作为 `forum` 发送。
- 从该页唯一 `/post` 表单读取正整数隐藏字段 `forum`，并核对 `.compose-title` 中的目标板块名称、请求路径和本地板块编号一致。拒绝缺失/重复编号、其他板块或含 `res/resto` 的回复表单。
- 按官方脚本提交 URL 编码字段到 `/post/post`，正文为 `comment`，板块为网页提供的 `forum`，可带 `title` 和 `img[]`。新串不发送回复目标 `res`。
- 图片继续通过 `/post/upload` 上传并保存回执；后续失败保留草稿和回执，手动重试复用已上传图片。发布成功仅接受 `code=1`，上传成功码 `200` 不能视为发帖成功。

## 验证与限制

复用回复流程的验证码、权限、频率、未知结果、附件校验与失败恢复逻辑；新增发串不会触发自动重试。远端发帖成功后才清理草稿。

本地 HTTP 测试覆盖两站纯文字与图片新串、动态 Cookie/hash、板块映射、目标错误、回复表单混入、验证码、重复表单与外源 action；Store 测试覆盖新串/回复提交失败、上传进度保留及成功清理。CLI 验证预览和错误确认码零请求；TUI 验证 c 编辑与预览、无饼干弹窗及小窗口提示。

只对真实站点进行公开 GET，并将下载的两站新串表单交给实际解析器验证。未向真实论坛发帖或上传，真实饼干的发言权限和服务端最终接受结果仍需用户实际使用确认。
